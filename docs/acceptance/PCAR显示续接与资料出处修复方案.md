## 二、施工

### 1. 修复正文显示续接

- 按回合、发布项、片段及正文指纹确定稳定的渲染标识，记录写入前、写入后及提交回执的阶段。补齐文档隐身、会话变化、元素脱离、坐标遮挡、连续帧未完成及桥接异常等原因代码。
- 正文已生成而呈现不确定时，保留可核对的原稿入口。有确定未呈现的记录时，沿同一个片段标识续做。效果未知时先通过设备回执对账，保留「查看本轮回复」入口。只有确认呈现的片段才进入可见历史。恢复始终使用原稿。
- 查前发言用相同的呈现账本。完整显示回执到达后才放行公开工具。来源撤回、授权变化及重开仍按原回合核对。

先用红框原稿及未知回执复验。再验遮挡、切换会话、滚动、重开、撤回、多窗口及回执丢失。每个回合只生成一次，气泡按稳定标识显示，未知位置的工具派发须有实际查前显示依据。

### 2. 修复补查对象漂移

- 把理解出的对象与公开外发依据分别保存。首次理解已对到当前对象时，恢复优先为它找同一会话内获准的公开任务、来源片段或主题修订，保持本轮所问属性。
- 恢复时可继续用当前原话和已定位的对象。换成另一对象需要当前话轮的明确依据。范围仍不能核准时，沿原对象和已知资料交流。
- 用这次的两个相邻人物、代词追问及主动换题分别验收。核对最终冻结的对象、公开原文片段及实际发出的工具查询。J4 仍按本地优先路线判断需要资料与否。

### 3. 去掉按可信度挡资料的规则

**社区爆料、传闻和推测都可以成为伴侣讨论的依据。** 保存原话和出处，把传闻、预告、公告视作原来源的性质。用户问社区在猜什么，相关帖子就能回答。用户问官方公告说了什么，按所问出处取材。来源彼此矛盾时，保留各自说法并让角色取用。

| 要查的入口 | 改法 |
| --- | --- |
| 现行公共取材 | 盘点 `public_lookup_study.supported` 及已审 J5 的「可信程度」条件。J5 只核对对象、事件、版本、时点、属性及来源原话是否支持所说内容。原生综合的引用关系可以排序，`cited_selection` 中据此淘汰合格旁支的规则需移除。普通社区材料与官方材料同样保存到本地，再交给角色。 |
| 旧资料读取与共用流程 | 盘点 `knowledge_revisions.project` 的传闻筛选、`local_knowledge.search` 的传闻入口条件，以及旧整理入库、记忆复用和共用频道。取消可靠性门槛。有出处的原文、历史版本、冲突说法都可按所问范围取得，资料可读性与授权继续由来源标识和回执核对。 |
| 正文与出处 | 对作为查证结果交付的断言，关联本轮实际读取、获准使用的本地资料标识与原文片段。新资料先保存再引用。正文保持角色自己的自然表达，出处可在详情核对。缺少有效绑定时处理无据断言，角色仍可接话、表达意见或和用户一起讨论猜测。 |
| 查证状态 | 「刚查到」由本轮实际工具与资料读回支持。回顾已经聊过的材料沿现有来源和对话上下文，给出处或接住这次讨论都可以。 |

程序负责核对引用标识、原文片段、主题和版本范围、真实工具及显示状态。一个随意填的来源号不能证明正文已得到原文支持。新合同应让查证断言与片段有可复核的绑定，再用同源对照和无依据样本核验。对普通聊天、角色态度和明显的推测，继续由模型自然表达。

## 三、验收口径

| 用例 | 通过要求 |
| --- | --- |
| 红框正文已生成但呈现未知 | 原稿可核对，回执原因明确；同一片段确认后只出现一次。 |
| 同会话两个对象，省略名字追问 | 保持当前对象或明确证据缺口。工具实际查询与本轮属性一致。 |
| 社区爆料、作者猜测、互相矛盾的帖子 | 合法相关原文均可入库、召回和使用，记录出处和语境。 |
| 本轮没有事实来源，或引用了别题 | 无据查证断言不能借任意引用通过。角色仍能继续交流。 |
| 本轮没发起查证却声称刚查到 | 状态合同能识别这处不一致。 |
| 普通闲聊和关于猜测的自然讨论 | 角色表达自然，实际回复由作者评阅。 |

本轮先交付实窗排查与施工方案。目标解析、J5 及正文中需要改变的模型输入按项目规则另行交审。
