# PCAR 1.4.2 安卓真机性能实测

2026-11-25 · V2505A · Android 17（API 37） · 8 个逻辑核 · 系统识别内存 14.9 GiB

**PCAR 前台内存约为同机手机 QQ 的 28%，短时前台 CPU 占用接近。** 在连续观察中，PCAR 前台无操作时的 CPU 占用主要来自应用主进程，回到后台后迅速下降。独立 ARM64 验收包连续完成 12 轮本地组合负载，CPU 采样峰值约为 1.88 个逻辑核，内存 PSS 峰值为 740 MiB。

## 与手机 QQ 同机对比

在同一设备上依次将手机 QQ 9.3.80 和 PCAR 1.4.2 切到前台，各等待 12 秒，再静置采样约 24 秒。每个前台窗口有 9 个有效样本。PCAR 统计主进程与归属该应用的 WebView 渲染进程，QQ 统计当前安卓用户下的主进程和随窗口运行的子进程。期间未发送消息。后台数据来自另一款应用处于前台时的同期采样。

| 场景 | PCAR CPU | 手机 QQ CPU | PCAR PSS | 手机 QQ PSS |
| --- | ---: | ---: | ---: | ---: |
| 各自前台静置 | 73% / 89% | 72% / 92% | 258 MiB | 907 MiB |
| 后台驻留 | 0% / 0% | 13% / 18% | 206 MiB | 732 MiB |

CPU 为中位数 / 采样峰值，一颗逻辑核为 100%。CPU 来自 ADB 的约 1 秒采样，PSS 来自 Android 内存诊断并按进程加总，表中内存为中位数。这组对比表明，在本机的短时静置条件下，PCAR 的驻留内存明显低于 QQ，前台 CPU 的差距约为 1 个百分点。

## PCAR 启动与本地组合负载

| 场景 | CPU 中位数 / 采样峰值 | PSS 中位数 / 采样峰值 |
| --- | ---: | ---: |
| 正式版前台，进程冷启动后前 15 秒 | 71% / 115% | 258 / 260 MiB |
| 正式版前台，启动 15 秒后至切入后台 | 69% / 89% | 261 / 263 MiB |
| 正式版按 Home 后约 18 秒 | 0% / 41% | 216 / 259 MiB |
| 独立 ARM64 验收包，预热后反复执行本地检查 | 103% / 188% | 607 / 740 MiB |

- **启动和调度。** 5 次进程冷启动中，Android 报告的 Activity 显示耗时为 156–328 ms。最后一次启动后持续观察约 72 秒。启动 15 秒后，主进程 CPU 中位数为 66%，WebView 为 3%。一条名为 Thread-4 的线程多次消耗单核约 37%–41%，采样时运行在 CPU 6 或 7。热点目前定位到线程，仍需核对调用栈和任务来源。
- **后台内存。** 按 Home 后，PSS 中位数从 261 MiB 降至 216 MiB，同时 Swap PSS 中位数从约 0.5 MiB 升至约 73 MiB。部分内存页被换出，PSS 差值不能直接作为应用主动释放的内存量。
- **本地检查。** 独立验收包在约 90 秒内完成 12 轮，覆盖 SQLite 完整性、FTS5、本机 HTTP/TLS、Flash 本地分词及 BGE 向量检索。每轮核对 37 个向量，对 12 个查询各检索两次。设备可用内存最低约 3.8 GiB，12 轮均返回通过。740 MiB 包含长文本分词等开销，本轮未测 SQLite 和 BGE 各自的峰值。

## 验证范围与后续优先级

本轮采用单台真机、短时静置窗口和固定小语料。长期前台驻留、真实多轮对话、大历史库和低内存设备仍需对应负载的实测。加装散热器后已停止温度采集，本报告仅采用 CPU 与内存数据。

性能验证优先覆盖 **Android**。下一步先定位正式版前台无操作时持续占用 CPU 的任务，再视需要测量不同库规模下的 SQLite 查询和 BGE 召回开销。

**Windows 压测安排在后续。** Windows 对 PCAR 使用的 Python、SQLite 与 WebView2 具有成熟的运行支持。根据项目方的日常使用观察，PCAR 在常规 Windows 环境下占用较低，因此当前优先核查 Android，Windows 后续重点补测资源受限等极端场景。上述 Windows 判断来自日常观察，量化基线以后续压测为准。
