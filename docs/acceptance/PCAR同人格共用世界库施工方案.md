# PCAR 同人格共用世界库施工方案

作者已批准施工，开发候选已接入。让同一实例内、同一个人格的桌面会话共用一份世界资料。旧窗口已查到并保存的合格资料，在新窗口匹配同一问题时可以直接召回。只有资料欠缺、过期或用户要求重新核查时，才按本轮授权补查。

## 一、现状和根因

当前工作台在同一个本地 SQLite 库内保存资料。联网通过取材、入库和本地读回后，文档仍按人格、会话及授权版本登记。正常语义召回先筛选允许读取的记录，再用 BGE 排序。换到新的会话后，旧会话资料在排序前已经被过滤。主题修订、可用于公开查询的前序来源以及续答回执也以当前会话为查找范围。仅打开一个新的界面并继续同一个会话，应沿用原来的资料边界。应通过会话 ID 与实际搜索回执核对用户反馈中的窗口切换。[入库](../../persona_runtime/local_knowledge.py) · [语义召回](../../persona_runtime/semantic_knowledge.py) · [查询语境](../../persona_runtime/lookup_target.py) · [主题修订](../../persona_runtime/public_lookup_study.py)

隔离库只读盘点有 53 条会话级文档，分属 7 个会话，其中有 2 组同人格、同网址、同内容的文档跨会话重复。现有向量缓存已经按模型和文本内容复用。预计收益主要来自跨会话召回、少发重复的公开查询、减少重复文档和片段。实际节省量以改动前后的文档、字节、向量及工具回执对账为准。

## 二、共用范围

| 对象 | 归属与处理 |
| --- | --- |
| 世界资料 | 按本机实例和稳定的人格 ID 建立逻辑库。通过现有入库核验的公开原文及能追溯到公开出处的片段，可以在该人格所有桌面会话召回。公开的社区内容保留原有说法、时间和确定程度。 |
| 内容与回执 | 共用正文和索引，查找权限、工具派发、来源取得时间、原话轮、引用及气泡继续由原会话记录。一次取材和后续在另一窗口引用，分别留有自己的回执。 |
| 私有会话内容 | 原会话里的聊天、草稿、私人材料、人物互动记忆以及尚未明确归属的更正，继续使用原有会话授权。仅当原文能够证明是公开资料且符合共享范围时，才可进入人格世界库。公开 URL 不能证明整份工具合成结果都可以共享。 |
| 人格边界 | 使用人格 ID 核对。改显示名照常共用，同名新建、人格副本及其他实例保持独立。桌面之外的频道沿各自授权和现有部署计划。 |

换窗后的连贯性来自已经核实的世界资料和其中的公开话题依据。新窗口明确说出作品、人物、事件或贴出链接时，可以直接查本人格库。由当前话或明确引用足以指向唯一公开主题的追问，可以续上该主题和已有来源。多个话题都讲得通时，先澄清所指。本轮可用的原文、事件与版本要随回复交接，角色可说当时查过或手头已有资料。新一轮真实派发并读回之后，才具备本轮新增查证回执。

## 三、施工工序

### 工序一　建立人格资料索引和入库资格

1. 复用现有 SQLite、授权过滤和 BGE，不为每个窗口另建数据文件或向量空间。新增人格级资料索引，把内容、来源修订、出处片段及各次取得回执关联起来。第一阶段引用已有内容，后续新写入走共用入口。
2. 按人格与规范化公开 URL 管理来源身份，按正文哈希区分修订。相同来源且内容一致时复用正文和段落标识，追加取得回执及来源条件。相同网址但内容变化时保留修订与适用时间。不同 URL 即使内容相同也保留各自出处，可复用相同内容或向量。许可范围不同的记录始终独立核对。
3. 入库资格从原允许外发的查询、已确认的工具返回、资料录入回执和原文片段逐项关联。供人格共用的部分必须是可验证的公开来源原文。合成摘要只有能绑定到原公开片段时才采用对应片段。私人附件、混有私聊的整理结果、结果未知、仅看过但未经入库确认的候选留在原会话。
4. 相似度用于召回和主题候选。能否归入同一事件及版本仍要看可核对的来源和事件范围。同一主题补查新增属性时，在已确认主题下追加修订与相关资料。两次来源说法不同则保留各自出处。相似度或标题相等本身不能用来合并事实。

**交付证据** 同一人格的两个会话取到同一来源后，正文和向量只建立一份共用记录，仍能查到两次取得回执。并发入库、重复提交和进程重开后记录一致。

### 工序二　接入跨窗口的本地优先路径

1. 将人格资料纳入当前窗口的本地候选。读库时同时核对人格身份、来源共享资格、撤回、有效期、当前角色和会话授权，以及模型接收方。单条合法的会话资料继续参与当前窗口检索。
2. 在现有 J4、目标解析和整组覆盖之间保存同一个本轮需求。用已经批准的自然语义召回和明确引用定位资料，既可使用当前窗口上下文，也可使用独立的公开主题索引。J4 无需新增取材但确实是同题追问时，可沿允许读取的已知资料接话。普通问候与明确换题不附带旧主题。
3. 整组覆盖足够时直接作答，公开工具调用为零，界面出处能追到旧窗口的公开来源。若本地只有日期而本轮要时刻，保留日期依据，继续沿现有查前提示和公开范围核对补查时刻。补查仍缺时刻时，交付有出处的部分答复。缓存日期、当前读取时间和本轮新取得时间分别记录。
4. 公开查询仍仅使用本轮获准的公开主题和属性。关闭本轮联网时，已允许读取的世界资料仍可用于本地路径。发给上游模型的资料继续遵照当前会话的接收方授权。权限或来源发生变化时，发布前再次核对。

**交付证据** 在窗口 A 查回并入库后，于同人格窗口 B 用明确同题及改述各验证一次。新窗口读到相同公开片段及原出处，实际搜索次数为零。追加缺失细节时才补查，结果回到同一主题。

### 工序三　归并旧记录和处理撤回

1. 先对旧记录做只读扫描，列出重复组、可直接关联的公开来源、冲突修订、缺出处或权限不清的材料和可节省的字节。随后只将可证明合格的文档及片段关联到人格世界库。保留旧文档、事实 ID、偏移量、原回执及引用。权限不明的资料沿原范围使用。
2. 归并按批次和稳定证据标识执行。入库与关联需可重跑并可在中断后恢复，避免把一次获取记成两次。同一主题中来自不同事件、版本或时间段的字段保持区分。一个已撤回的来源不能由另一会话副本重新出现。
3. 撤回区分实际操作。撤回当前会话授权后，该会话停止向已失去授权的模型派发；依赖该授权的源证据停止复用。另一份来源若有独立且仍然有效的取材证据，可以继续支持同一公开内容。人格级撤回则使该来源的对应公开修订在全部窗口退出候选。撤回或更正传播到索引与迟到回复校验，历史回执保留原样供核对。
4. 影子索引先只读对照，再对隔离候选启用共享读取和新写入。旧回合继续沿冻结契约。关闭候选时停止新范围的读取，旧会话仍按原路径可用，已接收的外部调用按原回执对账。物理去重与旧内容回收在引用、备份、撤回和回退对账通过后另行处理。

**交付证据** 迁移前后逐项对照旧引用，重复跑两次归并，验证没有重复新增。对照窗口撤回、人格级撤回、来源更正与独立来源仍可用的结果。统计逻辑去重及实际字节分别留档。

## 四、隔离验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| 同一会话换界面或重开 | 原资料与气泡继续可读。命中时零新增公开工具请求。 |
| 同人格新窗口问同一公开问题 | 命中合格的旧资料、引用可查，零新搜索及查前预告。 |
| 同人格改述、承接唯一已指明的公开主题 | 召回同一条相关公开证据。未说明所指且有多个候选时给出澄清，不串题。 |
| B 追问 A 尚未查到的具体时刻 | 先保留 A 的日期及出处，再按授权补查时刻。官网仍未给时刻时交付部分答复。 |
| 两个窗口补充同一主题 | 可一起召回相关段落。文档和片段稳定复用，两个获取回执都可定位。 |
| 同名人格、不同会话中的私聊和私人附件 | 人格 ID 隔离有效。私有内容不出原授权范围。 |
| 撤回、改口、换接收方或关联网 | 失去资格的依据不再派发或交付。允许使用的旧世界资料在本地可继续读。 |
| 同网址不同修订、社区与官方的不同说法 | 原文、获取时间、适用范围都可回查，覆盖结论不把不同事件合成一个。 |
| 并发、断电重开和回退 | 旧引用有效，索引不会重复膨胀，未知结果不自动重发。 |

验收顺序为只读盘点与离线回执复算、隔离窗口真实对照、作者体验签收。每个实窗用例核对读到的原文、实际工具派发次数、最终气泡和可展开的出处。记录同题命中、缺口补查、误召回以及重复正文和片段的变化。现有 G-Auto 签收回执继续作为基线。

## 五、开工与作者参与

先实施工序一的索引及授权验证，再联调工序二的召回和补查，旧库归并与回退准备随后合并验收。优先复用已审装配，实际模型可见的资料范围发生变化时，按项目总则核对具体输入、接收方与实窗用途。正式实例在测试通过并签收后另行登记。本方案阶段由作者确认多窗口共用范围，实窗阶段只需在同一人格的两个窗口分别授权并测试实际追问和换题。[模型输入与提示词写作总则](../模型输入与提示词写作总则.md)

## 六、开发候选与工程核验

2026-11-22，开发工作台接入 `persona-world-v1`。登记单位为实例和人格，新回合冻结其共享读取范围。目标解析可使用可读的同一公开主题的来源标题。整组覆盖判断沿用现有输入结构。已选的原文在交给模型、生成回复及展示出处时仍须可读。旧窗口的原问题、聊天记录和附件按原有会话合同处理。

桌面聊天入口的离线回归使用两个独立会话和可计数的模型、工具替身。A 已入库时刻后，B 在零次新公开调用下取得正文和出处。A 只有日期时，B 保留日期并补查具体时刻。普通问候不调用覆盖判断；明确引用同一公开网址时可在本地接话。两次独立取回同一内容时，各有取得回执和事实 ID，共用稳定片段标识和一份资料正文。来源更正、撤回和更换模型接收方的用例均检查旧片段能否继续读出。

旧库副本内有 53 条会话文档和 7 个会话，47 次取得的资料符合数据库中的归并条件，涉及 45 个不同片段。第二次归并新增零条；中断后两路并发恢复得到相同结果。旧回执和原正文全部保留。这份副本的 SQLite 文件因新增索引从 19,107,840 增到 19,193,856 字节。两组旧重复正文合计 547 字节；实际物理去重从新取得的合格正文生效。

[归并和启停工具](../../scripts/pcar_persona_world.py)在指定实例与人格范围内提供 `audit`、`backfill`、`enable`、`disable`，以及按网址或指定修订撤回的 `withdraw-source`。盘点和分批归并可先在副本运行，启用时补齐期间新提交的取得回执。关闭候选后，已生成的旧引用和原始回执可供核查。

在调整模型线路前，把副本的登记资料与会话授权文件、当时的接收方对账，47 条已建索引的记录里有 6 条具备跨窗读取资格，来自同一窗口。其余 9 个历史窗口的接收方不同。在仅依据数据库记录进行的向量检索对照中，10 个原查询有 9 个能在前六个结果找到原来源，另一个在第 2 位找到给出同一答案的另一来源。这个数字反映排序表现。更换模型线路后须按新的实际接收方重新核对。

真实工作台的两窗聊天、公开工具是否实际派发以及作者的自然度签收，按第四节单独验收。开发候选的模型接收范围已列入私有的双窗口实测审阅材料。

### 关联对象实测修复

2026-11-22，隔离会话 B 的一次双对象追问把裸指代当成公开对象，实际产生两次工具派发。上下文已经包括显示回执和可核对的公开依据。修复复用原目标解析职责。识别到独立指代后，保留原属性和精度，以同一上下文补一次绑定。双对象指代必须补齐两个对象。补绑失败时本轮不派发公开工具。
