# PCAR 私聊取材与回复交付修复方案

**工程候选已实现，模型装配已审并登记隔离实窗。** 适用于当前开发工作区和验收角色的隔离工作台。实窗中的问题从查找目标、资料是否够用一路传到正文和气泡。施工目标是让这四个环节沿同一轮任务和原始回执工作，用户能顺畅追问、换题和改口，程序能在缺资料或失败时继续到明确结果。

## 一、施工依据与范围

| 实窗记录 | 可以确定的事实 | 对应改动 |
| --- | --- | --- |
| 普通问候 | 正文已生成并放行，首次气泡因 Windows 遮挡检查被移除。修复后，原稿在原窗口以一个气泡显示，并进入对话历史。 | 以已通过的聊天页交付为回归基线，核对显示与取材状态的交接。 |
| 第一次问版本开服时刻 | 目标解析返回空结果，旧恢复条件未能接住。两份正文分别在无据查证和格式处理处失败。 | 把查找对象、当轮所问和公开查询的授权分开保存，明确空结果和格式失败的处理。 |
| 新会话重跑 | 公开标题与当前提问均已选出，但模型把标题里的名单标为属性，把当前问题标为限定词。补查解析又返回空结果，最终搜索次数为零。 | 保留可核验的片段并重建合法选择，歧义仍存在时收束到当轮可说明的结果。 |
| 原窗口补试 | 首轮目标解析正确。四条资料被判完整，内容只给出上线日期。本轮跳过联网，正文据实交付了部分答案。 | 本地可继续谈论的材料与足以停止补查的材料使用不同结论。 |

此前的原稿恢复、公开范围核验、出处复核和撤回机制继续做验收依据。本次主要施工区间是从 J4 选择取材到正文交付。已经签收的 G-Auto 连续消息和跨夜观察沿原回执核对。QQ、正式包安装及自动记忆独立复核沿各自项目计划推进。[故障及实窗记录](PCAR显示续接与资料出处修复方案.md)

## 二、本轮任务如何交接

沿用本地 BGE 对自然语言提问和可访问原文做语义召回。一个取材回合保存一份**本轮资料需求**，覆盖用户希望了解的事情及答案应有的精度。多件事一起询问时，仍以完整提问和自然上下文做整体判断。程序记录能回答的依据和尚缺的信息，角色依旧按正常对话组织发言。

| 记录 | 最少保存的信息 | 下游用法 |
| --- | --- | --- |
| 本轮资料需求 | 回合、输入消息和版本、当轮所问、承接的话题及依据、对象或版本已确定到什么程度、明确的精度或时效要求、模型决策回执。 | 本地与公开取材沿同一个问题走。用户改口时形成新回合的需求，旧回执保持可查。 |
| 外发查询及授权 | 实际查询、原文片段位置、授权会话及版本、已核对的接收方、必要的查前显示回执。 | 程序核实本轮可公开发送的文字。语境已经理解但无法安全形成公开查询时，本地材料仍可用。 |
| 资料覆盖结果 | 一组实际读到的来源及修订、整体覆盖结论、能支持本轮答案的引文、仍缺的信息、回执或判断失败原因。 | 本地已答全时直接交给正文。本地只答了一部分时，按现有授权与取材规则决定补查，并继续保留这部分。 |
| 取材和交付状态 | 本地读到什么，外部工具是否派发及确认，正文生成与复核，气泡显示及历史入账。 | 正文生成使用实况。界面能说明正在等什么、已收到什么。完成率可分别核对任务和交付。 |

以本次开服追问作说明。已读原文只给上线日期时，整体结果保留该日期及其出处，同时标明具体时刻缺失。预告或节目标题可以帮忙定位主题。公告发表时间、帖子时间、抓取时间、发布日期各保留自己的含义，均不能填作所问事件的具体时刻。若材料只给本地时间，则按来源已有的时区信息交付。来源不明时保留时间表述的适用范围。

资料需求和覆盖结果优先附在现有回合回执上，并带版本及输入摘要。复用已经存在的查询指纹、来源修订及显示回执。恢复时校验当前输入、会话和授权版本，再继续尚可执行的步骤。

## 三、施工顺序

### 工序一　固化故障基线和回合记录

**入口** [研究回执](../../persona_runtime/public_lookup.py) · [工作台回合投影](../../persona_runtime/workbench_timeline.py)

1. 用已保存的实窗证据建立基线。保留首次空解析、引文角色错标、两种多余字段、无搜索回执却声称已查、日期被判足够、问候气泡被删这六类记录。原始消息、实际查询、来源、模型结果、正文、显示回执以原标识关联。真实材料与完整提示留在既有私有验收目录。
2. 为新回合加最小版本化记录，明确哪些值来自模型建议、哪些是程序检查后的结果。读旧数据时保持旧回执原义。缺失的覆盖信息按旧版未知处理，历史上标成命中的回合不回填成新版本已答全。
3. 把失败分到实际环节。至少区别范围未定、授权不可用、等待额度、未派发、工具结果未知、返回部分资料、正文格式失败、无据查证断言和显示未确认。等待有现成恢复时间时沿用真实时间。
4. 冻结基线对照。后续改动应能按每个原始标识解释行为差异。先做读取、持久化和回放，再接正式路由。任何新的契约不得改变正在运行的旧回合所绑定的材料与接收方。

**验收出口** 原回执可逐轮复现，各环节失败可独立观测。旧会话、重开和撤回相关测试可通过。此工序可以用保存回执和本地替身完成。

### 工序二　把语境理解和公开查询接在同一需求上

**入口** [目标解析及逐字核验](../../persona_runtime/lookup_target.py) · [公开范围核对](../../persona_runtime/public_lookup.py) · [本地取材路由](../../persona_runtime/local_lookup_route.py)

1. J4 继续只判断是否需要取材，复用现有授权来源和连续对话材料。使用现有专职目标解析理解本轮想了解的事情。用户当前的所问优先，上一轮公开查询、资料标题和明确引用用于定位对象。把结果落入同一份本轮资料需求，然后供本地向量检索、公开查询装配及来源覆盖判断共用。
2. 公开发送前校验引文位置、来源归属、版本和授权。程序可以修复一一对应、可由原始位置证明的格式或标签错误。已有的错标修复作为兼容入口。当多个主题都合理、当前所问有两种解释、资料只是上一次节目标题时，保留歧义，不自动选定一个版本或替换为旁边的角色。
3. 既有收窄恢复归为**一次有依据的补救**。有明确引用或唯一、仍有权使用的前序公开话题时，第二次解析保留该话题原文和当前输入。空结果与结构无效共用相同的范围规则。若仍无法选定，保留本地已知范围，进入现有澄清或事实状态反馈。不同失败原因用各自回执记录。
4. 将公开授权核验留在外发边界。对只查本地、已禁联网、无需新增取材和授权撤回的情况，保留现有合法本地路线。用于本地判断的私聊原文与送给公开工具的查询保持独立。如果完成前用户发送新话题或取消，依现有队列和版本判定处理未派发的工作。

**验收出口** 改述、隐含指代、明确引用与换题均能保住本轮问题。公共工具接收的是通过授权核验的实际查询。原错误片段可离线复算，未定范围时观察到零公开工具派发。

### 工序三　以整体资料覆盖决定本地回答或线上补查

**入口** [公开选材与入库](../../persona_runtime/public_lookup_study.py) · [本地命中与补查](../../persona_runtime/local_lookup_route.py)

1. 召回继续以现有向量相似度排序，程序按授权、撤回、时效、版本和来源完整性限制可读材料。上轮已合法入库但未用于当时正文的段落仍可参与本轮召回。保留相互矛盾的材料及各自出处，社区消息保留原有确定程度。
2. 优先将 J5 收束到**整体材料能否回答本轮问题**这一项。送入同一轮资料需求与一小组获准原文，输出整体覆盖、支持引文和仍缺的信息。程序核对被选出处、原文位置、输入及来源版本。排序与召回由现成向量路径承担，是否联网由程序按覆盖结果和授权决定。单条来源相关性与整体覆盖如果在实验中确实需要独立模型判断，各任务使用各自专职节点，具体装配另行评审。
3. 本地整体覆盖完整，且材料适用本轮时效和范围时，直接回答。只有部分资料时，把已有依据留在本轮，并在可外发时用缺口组织一次补查。资料不足时走已授权的公开路线。覆盖判定无有效回执时，标为无法确认，保留已授权原文和可核对的真实状态。只查本地或无权外发时，以已有信息继续或说明差哪一部分。
4. 联网结果先保存，再沿同一个本地读取路径取回。来源确属同一主题时，在现有资料修订下追加引文和获取回执。相同文档和片段复用原标识，保留每次取得的时间。材料指向另一版本或另一个事件时须保留各自的出处和范围。新旧资料用同一轮需求判断能否回答。明确需要更具体或更新的信息时按已经审定的查证策略处理，完整性或新鲜度缺失均在回执里保留。线上仍未补足、页面无法读取或工具结果未知时，角色可使用先前确有出处的材料，程序提供本次实际状态。
5. 过渡阶段先把新判定作为只读对照，不据此决定外发。用这次四条只有日期的来源收集新旧差异，再验证有对应时刻、只有较晚的文章发表时间、版本标题和正文指向不同事件的样本。稳定后再在隔离候选启用真实路由。保留六段一类的现有小上下文预算作为起点，按实测调整调用成本。一次整组评估可以替代同一用途的多次逐条判定，实际调用量在对照中记录。

**验收出口** 日期资料留在结果中，具体时刻缺失时能够触发有授权的补查。已有同一事件时刻的本地材料直接作答。冷查和温读对同一批获准材料得出一致的覆盖结论。只有来源类型不同、确定程度不同或表述不同的相关材料均可参与判断。

### 工序四　让正文、失败反馈和气泡各自兑现真实状态

**入口** [正文装配与重写](../../persona_runtime/ordinary_reply.py) · [出处复核](../../persona_runtime/reply_provenance.py) · [工作台显示](../../persona_runtime/workbench_web/persona_import.js)

1. 正文只收到本轮确有的材料、范围和工具进度。只有本轮实际取得并在本地读回的材料才能支持刚取得结果的表述。沿上轮出处回顾、讨论社区说法和角色有标明的猜想继续可以自然表达。出处复核核对角色作为取材结果说出的断言与原文、进度是否对应。
2. 格式归一化用于去掉可验证、无用户内容的回显，例如与既定动作完全相同的字段和短答空长文。未知字段、冲突字段、错误引用以及无据查证各记原始原因。可修复的正文沿现有一次重写额度带入具体错误信息，仅在现有或新获批装配范围内使用。未公开的假结果留在审计稿，不进入可见聊天和记忆。
3. 两份正文都未能交付时，工作台用实际回执说明本轮情况。范围未确定时显示搜索未发起，锁住逐字公开边界。材料已经查回且仍允许查看时沿原资料入口可读。额度暂停显示所等额度和可恢复条件。工具效果未知时保留原请求，后续按回执对账，避免重复外发。错误文案属于界面反馈，不作为人物发言。
4. 普通正文沿已核实的聊天页显示路径结算，原稿与片段标识贯穿确认、历史与重开。查前继续遵照已审的预告和可见性程序要求。退出、遮挡、切会话、撤回及迟到回执用真实的页、会话和来源版本判断。隐私和公开授权在外发之前再次核对；来源变化时禁止迟到稿继续引用。

**验收出口** 用户能区别暂时等待和本轮已结束。答复出现时只有一个正确的正文气泡，历史引用读到相同正文。现有查前保护、未知请求不重发及普通问候显示均通过回归。

## 四、验证矩阵

每个案例都核对实际收到的原话、所问精度、最终查询、是否派发工具、本地读回、正文所用出处以及真实气泡。纯聊天和取材回合的终态用各自应有的结果核对。

| 场景 | 工程通过条件 |
| --- | --- |
| 同一版本，问具体开服时刻，本地只有日期 | 本地保留日期与出处，记录时刻缺失。有授权时发生一次补查，核对派发查询中的事件和所问。 |
| 同一要求，本地已有对应时刻 | 本地证据能对上同一事件与精度。正文引用对应来源，新增线上调用为零。 |
| 补查后仍只有日期，或网页读取失败 | 保留已核实日期和缺口。区分工具部分失败与已有来源，正文或界面如实交付。已成功的材料可保留，未确认请求按原回执处理。 |
| 两个版本或预告与正式上线混在一起 | 不拼接不相干版本的日期或时刻。有足够依据时完成定位，仍有歧义时保留真实缺口。 |
| 同一主题补齐另一条信息 | 新材料和旧材料在同一资料主题下可被引用，各自有入库回执。已有文档与片段标识复用，继续追问能召回两轮资料中相关的段落。 |
| 原实窗引文标错及同一问题改述 | 故障原样能回放，修复后主题与当前原话有逐字出处。改述和换题通过通用路径验证，不依赖具体游戏名或固定措辞。 |
| 社区爆料、资料互相矛盾、旧资料撤回 | 社区原文可以参与取材，正文保留说法归属与确定程度。已撤回来源不再参与新取材或迟到稿发布。 |
| 只查本地、关闭联网、授权在派发前变化 | 公开调用为零。授权还有效的本地材料可继续使用。 |
| 已授权的主动查找与普通闲聊 | 前者能触发需要的取材，后者零误联网、不进入检索正文的出处复核。旧有连续对话资料仍可按规定被回顾。 |
| 空解析、格式错、无据声称已经搜索 | 查找范围未定时零外发。无害回显可兼容，未绑定的查证断言不发布。两次失败后聊天页反馈真实状态。 |
| 额度等待、切会话、遮挡、回执丢失、重开 | 能按原回执接续。已确认未派发才可重送同一操作。工具效果未知不盲重发。确认交付的气泡和历史各一份。 |

验证分三个台阶。第一台阶用原回执、真本地召回及数值化接口替身核对工程路径和失败注入。第二台阶用同一组资料比较新旧覆盖判定，记录每轮模型调用、外部派发、等待和实际回复。第三台阶由作者在隔离实窗用原题和作者选择的改述、换题进行体验验收。固定原题的通过只能覆盖复现路径，跨话题结论来自真实对照。

**签收按三个结果分别记账。** 取材侧确认该查时确实派发且范围正确。答复侧确认证据是否覆盖所问以及角色是否把已知和缺口说清。交付侧核对气泡、原稿和历史。三个口径分别记录通过率、首次失败点和等待时长，保留全部尝试及回执，不用合计测试数替代工程或体验结论。

## 五、激活、回退与作者参与

- 隔离候选采用版本登记，新旧回合按各自冻结的协议继续。先对照，再启用新路线。只有查过的资料与工具状态得到同一回执验证，才用新逻辑决定补查或交付。失效时停用该候选，切回已签收登记。进行中的外发按确认状态结算，保留原稿、来源和显示历史。
- 工序一至四的本地结构、回执和离线替身验证可以先完成。任何新的模型原文、输出示例或实际输入内容变更，都按项目总则先取得具体写作授权，再以版本、接收方、输入范围及调用用途交作者审阅。旧批准沿其原装配使用。[模型输入与提示词写作总则](../模型输入与提示词写作总则.md)
- 作者当前只需审阅施工范围和验收口径。隔离实窗阶段再开启该会话的隐私和联网授权，用自己的说法进行追问和换题，评估发言是否自然、反馈是否及时。工程侧负责实际查询、覆盖、调用和气泡的对账。正式安装在隔离验收和作者签收之后另按项目流程办理。

**优先施工** 工序一和工序二先明确记录和查询边界，接着完成工序三的「只有日期仍补查」。工序四与前述工作并行完善终态反馈，在真实工具启用前汇合。达到验收矩阵的隔离复验条件后，再安排实窗。
